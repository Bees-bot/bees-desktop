# Team process continuity

Each process run, including its delegated work, belongs to one user on one machine. Separate runs of the same process can have different owners. Starting or explicitly continuing a run establishes ownership once; it has no timeout and needs no cloud heartbeat. Closing Bees, losing connectivity, completing work, or a colleague opening the run does not relinquish control. The owning machine can recover from its local history after a restart.

The run conversation offers **Relinquish control** on the owning machine. Bees blocks new admissions, cancels the run's local workflows, waits for agents and tools to finish stopping, and writes `.bees-handoff.json` beside the run's inputs and outputs. It then publishes the final shared metadata and explicitly relinquishes ownership. If a step fails, ownership remains reserved and **Finish relinquishing control** retries the handoff.

Another team member chooses **Continue on this machine** after relinquishment. Bees first verifies the checkpoint against the server's stage metadata, checks that every saved input and output has arrived intact, and checks the unfinished stages' local agents, tools, and folder mappings. An atomic server claim permits one claimant and rejects an outdated handoff. A lost claim response can be retried on the receiving machine; an interrupted local launch offers **Finish continuing**. Ownership and the local stages to resume are saved in one transaction. There is no forced takeover, automatic reassignment, or expiry recovery on another machine.

Continuation starts a fresh attempt of each unfinished stage using saved files, result summaries, discussion, and human review feedback. Completed delegated work stays completed. An interrupted review restarts its producer because detailed reviewer evidence remains on the original machine. Previous external actions must be reconciled before repeating them; previous approvals do not authorize new actions. This is stage continuation, not transfer of a live model session or Temporal history.

Run files and the checkpoint travel through the customer's selected shared storage, or by copying the whole run folder. Bees Cloud receives ownership and stage metadata plus existing short run summaries; it does not receive the checkpoint file, document contents, transcripts, model sessions, or credentials. Handoffs currently support at most 1000 unfinished items, 1000 files, 20 MB per file, 250 MB of files in total, and a 2 MB checkpoint. Larger runs remain on their current machine until their handoff fits those limits.

Background team sync uploads changed records only and skips its second pull when there is nothing to upload. Delegated work inherits local ownership without publishing or claiming before execution. Shared questions publish their work-item lineage when needed, then record one accepted response with its user, device, and server timestamp. Schedule occurrence deduplication and same-machine file locks remain: they protect duplicate scheduled launches and concurrent local file writes.

An unavailable owning machine leaves its runs reserved. The owner must return to that machine and relinquish control before anyone else can continue them.
