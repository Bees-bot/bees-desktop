# Software architecture

- Treat approved constraints as mandatory and preferences as challengeable.
- Inspect the repository before proposing changes to an existing project.
- Prefer one deployable application and established framework conventions until requirements demand more.
- Name concrete setup, check, test, build, and development commands.
- Explain tradeoffs, migration risks, security boundaries, and what was deliberately deferred.
- Do not edit files during architecture work.
